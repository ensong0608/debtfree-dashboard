# Next milestone: Capacitor authentication and device prototype

Architecture inspected October 16, 2026 Pacific: React 19 client dashboard, vinext/Vite React server routes on Cloudflare Workers, cookie-based Supabase authentication, D1 household storage and revision-checked JSON synchronization. No database migration is required for packaging.

Recommendation (engineering judgment): investigate Capacitor first, with a bundled React client entry that reuses dashboard components and accounting modules while hosted Worker APIs remain the backend. Current dist/client assets are not a complete standalone app: Capacitor requires an index.html and a built client asset directory; server-rendered routes/authentication cannot simply be copied into a WebView. Avoid treating a remote production URL wrapper as the finished mobile architecture. Compare the extraction spike against a native UI rebuild only if native usability/authentication cannot meet acceptance.

## Prototype scope and acceptance (unfinished)

1. Separate client bootstrap and platform adapters without changing production data or web auth. Use only isolated test households. Package an Android development build first as a proposed sequence; confirm platform priorities with the owner before account/signing commitments. iOS builds require macOS/Xcode and developer/signing access.
2. Implement Google authorization through a platform-supported authentication session, PKCE/state validation and narrowly allowlisted callbacks. Plan Sign in with Apple/equivalent compliant login for iOS; link identities without silently merging households. Do not embed provider login in an ordinary WebView or put tokens in deep-link query strings. Use Universal Links/Android App Links, correct domain association files, cold/warm invitation and auth routing, cancellation and replay checks.
3. Add a native session adapter with Keychain/Keystore-backed credentials. Current web HttpOnly cookies do not automatically become native secure storage. Preserve server-side membership checks and strict origin/CSRF rules; design a separately reviewed native API authentication/CORS path rather than weakening web protections. Test logout, refresh expiry, removed access and account-switch cache/outbox isolation with two independent identities.
4. Implement native Back behavior (close forms, navigate, then app exit), unsaved-form handling, safe areas, keyboard resizing/focus, status bars, lifecycle return/reconnect refresh and interrupted saves. Retain online editing and durable conflict-safe pending drafts; do not enable unreviewed offline writes.
5. Add real app icons/splash, app identifiers, Android signing and iOS provisioning, secure signing recovery and version/build numbers. Define API/data minimum client compatibility; older versions must refresh/block unsupported writes rather than drop group/interest/reconciliation fields. Validate API changes with the previous installed build.
6. On physical iPhone and Android phones test first launch, both logins/cancellation, deep links cold/warm, long forms/keyboard, large text/screen readers, Background/Back, offline/reconnect, payment retries, two-device edits, export/share and low-memory restart. Viewport simulations do not complete this gate.
7. Exit milestone with installable development packages, test identities, redacted device evidence and a documented compatibility/authentication decision. No public signup, store submission, purchase or paid commitment is included.

## Official requirements rechecked October 16, 2026 Pacific

- Capacitor v8 installation requires package.json, built web assets and index.html: https://capacitorjs.com/docs/getting-started . Deep-link association and app routing: https://capacitorjs.com/docs/guides/deep-links .
- Apple 4.2 requires utility beyond a repackaged website; 4.8 describes the equivalent privacy-preserving login requirement with exceptions; 5.1.1 requires privacy disclosures and in-app account-deletion initiation for account creation. Review sensitive financial-information/legal-entity scope before choosing account type. https://developer.apple.com/app-store/review/guidelines/ . Deletion guidance: https://developer.apple.com/support/offering-account-deletion-in-your-app/ .
- Apple's current upload rule uses Xcode 26 or later and iOS 26 SDK; the posted minimum target is iOS 13 or later. Capacitor's own minimum may be higher, so choose the stricter compatible target during the spike. https://developer.apple.com/news/upcoming-requirements/ .
- Current Google Play new-app/update target is Android 16/API 36. https://support.google.com/googleplay/android-developer/answer/11926878?hl=en .
- New personal Play accounts after November 13, 2023 require at least 12 continuously opted-in closed testers for 14 days before applying for production access; meeting the count is not approval. https://support.google.com/googleplay/android-developer/answer/14151465?hl=en .
- Google requires in-app and external account-deletion request paths and actual associated-data disposal/retention disclosure. https://support.google.com/googleplay/android-developer/answer/10144311?hl=en . Financial features declaration applies even on closed/open testing tracks; describe tracking accurately rather than claiming lending. https://support.google.com/googleplay/android-developer/answer/13849271?hl=en .
- Store privacy/Data Safety forms, required SDK/privacy manifests, reviewer access, signing and developer identity remain unfinished. Recheck official policies again at beta/submission time; no store approval is promised.
