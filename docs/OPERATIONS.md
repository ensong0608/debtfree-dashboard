# Household operations

Production is the Cloudflare Worker debtfree-dashboard with its existing DB binding. Never recreate the production database during release or recovery.

## Release gate
Use Node 24, npm ci, then npm run validate (lint, types, production build, full unit/API tests, three browser sizes, exact Worker dry run). Confirm wrangler whoami and wrangler deployments list --name debtfree-dashboard. Commit intended source, tests and documentation, push that exact commit, then npm run deploy. Record the commit and Wrangler version ID. Verify the Worker URL redirects an anonymous visitor to Cloudflare Access; in an authenticated browser verify Home and /api/health. Health returns 401 without membership, 503 if storage is unavailable, and 200 only after an authenticated database query. Never place an Access token in logs or public monitoring URLs.

## Monitoring and recovery
Cloudflare observability is enabled in wrangler.jsonc. Use Workers Logs to investigate non-2xx application responses and deployment regressions; configure account-owned alerts for elevated Worker errors and D1 failures. Alerts and authenticated synthetic monitoring require account-level setup and are not created by this release. The UI explicitly distinguishes pending saves, conflicts and local storage failures. A 409 means stop and reconcile; do not retry by force-overwriting the other session.

Export a private full JSON backup before importing or resetting. A pre-import checkpoint survives later autosaves and can be restored in Settings. Browser storage is not a substitute for a separately stored backup. Pending cloud edits are written to a per-user, per-tab durable outbox before sending, survive reload and retain their base revision. Export pending edits before clearing browser storage or closing a conflicted tab. Use Load latest household only after reviewing the conflict; it checkpoints the local version. Merge imports are explicit ID-based updates, not a general automatic conflict merge.

For database recovery, first stop writes and capture a private current D1 export using wrangler d1 export debtfree-dashboard-prod --remote --output <private-path>. Inspect available D1 Time Travel bookmarks using Wrangler and choose a timestamp together with the household owner. Restore into an isolated test database or validate a private export in local SQLite before any production restore. Check household membership, state count, parseability, revision, and representative balances. The executable tests/household-api.test.mjs restore drill verifies the schema/state copy and revision guard against local SQLite; it does not claim to be a production Time Travel drill. A production restore needs an explicit recovery decision because it can discard newer payments. Preserve the existing database and binding; never delete/recreate them as a shortcut.

## Compatibility and rollback
Payload version 6 adds signed balanceOffset, immutable per-account baselineBalance, monthlyCommitment, and per-month payment/minimum maps. Legacy versions 0–5 remain readable; migration preserves posted amounts and snapshots. Old clients without a revision receive 409 and must refresh. No SQL migration is required. Rolling back to version-5-only application code after version-6 saves requires restoring a compatible private data backup as well; prefer a forward fix. Do not silently strip correction offsets to make an old client read new data.

## Calendar and model policy
Dates use the browser's local calendar. Due days repeat monthly and clamp to the last day of short months. Ledger entries are posted facts immediately, including future-dated entries; scheduled payments are not a separate supported entity. Monthly forecasts estimate whole-month interest, not daily accrual. Promo expiration is inclusive: each forecast month evaluates the saved expiration against today's day shifted into that month, clamped at month end. Deferred-interest contracts and issuer statement reconciliation are not modeled. Balances display a zero floor; refunds/credit balances require explicit product work. Do not use the forecast as an issuer statement. Actual payments reduce the current month's available commitment, while the full commitment resumes next month and rolls over after payoff.
