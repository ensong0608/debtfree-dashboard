## Findings

**Observed:** existing Supabase authentication is server/cookie oriented, with relative requests and web forms. Packaging those pages does not supply a native session. Current strict Origin checks would reject ordinary cross-origin native mutations; merely adding a bearer header to HouseholdSync cannot fix bootstrap, lifecycle or other direct requests.

**Proposed native contract:** retain web routes and guards unchanged; add explicitly scoped `/api/native/v1/*` bearer routes in a separate development backend first. Reject cookies as an authentication fallback and reject mixed credentials. No global Origin exemption on the presence of an Authorization header. Use a narrow development CORS allowlist for the chosen WebView origin if web fetch is used, with no credential cookies; CORS is not authorization. Native HTTP transport remains an alternative requiring plugin review. Never spoof the web Origin to bypass lifecycle checks; extract shared authorization/domain operations behind distinct web-CSRF and native-bearer wrappers.

For every native read, export, mutation and bootstrap: validate token signature/allowed algorithm, configured development issuer, intended audience, expiry, subject, and server-confirmed user/provider; fail closed. Then perform server-only session liveness verification matching verified `session_id` AND subject against `auth.sessions`, through a narrowly privileged server service whose permissions and latency must be proven. Do not expose auth tables or privileged keys to clients. No positive liveness cache for the immediate-revocation acceptance contract. An unavailable check returns failure, not cached access. If that facility cannot be safely provided, this contract is blocked pending a reviewed authoritative session broker/revocation registry covering every revocation source; a local denylist alone misses external revocations. JWT validation or `getUser` alone is insufficient evidence.

Resolve D1 household and current role server-side after authentication, retaining scope mismatch rejection, no-store, bounded bodies, revision checks and all invitation/allowlist rules. Continue verified-email membership compatibility initially; carry issuer/subject as stable native identity. Do not silently migrate identity keys. Never authorize from `user_metadata`, requested household IDs or caller role claims. Google remains the existing policy: Apple-only users currently fail the mapper. Adding Apple or linking identities is a later explicit policy/schema review, not a native-wrapper switch.

**Browser/callback proposal:** development-only Supabase client with `flowType: 'pkce'`, `skipBrowserRedirect: true`, and provider-supported external browser login. Supabase mediates Google OAuth; Google's authorized redirect is the development Supabase HTTPS callback, not the mobile scheme. Final Supabase redirect is one exact registered app URL, provisionally `com.debtfree.dev://auth/callback`; manager must approve the actual application ID. Prefer verified App Links/Universal Links when domain association is available. Register warm `appUrlOpen` and cold `getLaunchUrl` handling before login, and deduplicate delivery.

Keep one bounded pending transaction with verifier, creation time and cryptographically random app correlation nonce. Bind the nonce to the exact allowlisted redirect and verify it on return; Supabase/provider owns upstream OAuth state, which must not be overwritten. Prove the chosen SDK preserves the nonce before implementation approval. Accept only exact scheme/host/path, one code, matching unexpired pending transaction and expected provider/backend; reject fragments carrying tokens, unsolicited links, replay, errors and arbitrary next URLs. Exchange once with the initiating verifier; clear transaction on success/cancel/timeout. No token, verifier or callback-URL logging. Capacitor Browser + App is a candidate, with version/plugin behavior and iOS cancellation/session behavior still unverified; no installation was performed.

Store refresh/session material and pending verifier using a reviewed Android Keystore/iOS Keychain-backed adapter; Capacitor Preferences/plain localStorage are not credential storage. Keep client secrets/service-role keys out of the bundle; only development public configuration belongs there. Serialize refresh, persist rotated credentials atomically, pause/resume lifecycle refresh deliberately, and revalidate server session plus household on foreground. A failed refresh/liveness check locks connected access and stops writes. Do not blindly retry a financial mutation after refresh; retain its revision and use existing conflict/identical-retry rules.

Logout/account switch must first stop sync, invalidate async generations, abort requests and hide financial UI. Online logout obtains server revocation/liveness denial and calls Supabase local-scope sign-out; clear secure credentials and caches. Offline logout can clear local access but must report server revocation as unconfirmed, never claim remote invalidation. Preserve pending drafts encrypted in a locked namespace accessible only after the same verified identity/household returns; never auto-submit them. Namespace caches, checkpoints and drafts by environment/backend + issuer/subject + household; do not adopt legacy unscoped cache. Keep synthetic demo storage separate. The native first milestone has no offline financial writes.
